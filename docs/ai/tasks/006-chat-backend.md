## 设计与实际边界

- Controller 使用受控 Express SSE：先完整校验和持久化受理，再 `flushHeaders`；原因是需要让前置错误保留标准 JSON，并以 response.close 可靠绑定上游 abort。事件仍完全遵循 `start/delta/done` 合同，15秒注释心跳、禁 Nginx buffering，断连不会当成功。
- 每次模型请求只有白名单 model、最近10轮 completed 问答及当前输入、stream/max_tokens/可选关闭思考；总32000字符预算按完整问答对剔除最旧轮次。答案最多16000 Unicode码点，超限保留部分并失败；max_tokens=4096。
- Mongo 单文档条件更新裁决最终状态，部分唯一索引保证单站主单活动会话。内存句柄只用来 abort；新进程 runtimeId 与持久化 expiresAt 用于读取时将旧 streaming 恢复为 interrupted，不自动重发。
- 模型地址生产仅 HTTPS，本地开发/测试可用回环 HTTP；fetch 禁止重定向，厂商原始响应不进入客户端错误。缺 Key 可正常启动但发送503，坏白名单在启动时失败或读取时安全报错。
- 模型调用与连接绑定，服务退出、超时、断连均尝试保存中断终态；数据库故障绝不发送 completed。如果数据库持续不可写，返回失败并提示刷新确认，后续恢复/过期读会回收残留状态；未承诺断电瞬间保全节流窗口内尚未落库的增量。
- 测试入口现要求调用者显式传入 MONGODB_URI，并在动态加载 AppModule 前固定 NODE_ENV=test；ConfigModule 在测试模式忽略真实 `.env`，防止补入线上连接或模型Key。
