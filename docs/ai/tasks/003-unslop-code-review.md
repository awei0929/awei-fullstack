## 主要发现

### 1. “打开演示”的文字与橙色按钮对比不足——已确认可读性问题

源码：[公开页样式](../../../frontend/src/pages/site/style.module.less#L215) 第 215–216 行；该按钮来自 [公开页组件](../../../frontend/src/pages/site/index.tsx#L324) 第 324 行。文字为 13px、普通字重，前景 `#fff8e6`，默认背景渐变为 `#eda029 → #cc7510`。根代理已在真实详情面板确认这些计算样式。

按声明的 sRGB 色值计算，结果如下。这里只比较梯度端点的理论对比度，不是整页或全部状态的 WCAG 审计，也没有把端点结果冒充逐像素测量。

| 文字色 | 默认亮端 `#eda029` | 默认暗端 `#cc7510` | hover 亮端 `#f0af46` | hover 暗端 `#cf7f1b` |
| --- | --- | --- | --- | --- |
| 当前 `#fff8e6` | 2.05:1 | 3.24:1 | 1.81:1 | 2.96:1 |
| 现有正文墨色 `#302e21` | 6.28:1 | 3.98:1 | 7.10:1 | 4.36:1 |
| 候选深墨色 `#211d14` | 7.73:1 | 4.89:1 | 8.74:1 | 5.36:1 |

建议保留橙色实体按钮，试用更深文字或调整暗端背景；仅改为现有 `#302e21` 仍不能保证普通文字达到技能采用的 4.5:1 目标。登录面板已使用深色按钮文字（[登录样式](../../../frontend/src/components/site-login/style.module.less#L48) 第 48 行），可统一表达方式，但其文字色直接套用到当前较深渐变也应重新核对。对应 AC01 的真实演示入口可读性。

### 2. 手机的次要内容已缩到 6–9px——已确认尺寸，建议优先改善阅读

源码：[公开页样式](../../../frontend/src/pages/site/style.module.less#L316) 第 316 行竖排标语为 6px；第 323 行档案标签 7px；第 325 行项目编号/精选 8px；第 328 行技术标签 7px、“打开作品”9px。第 352 行阅读页脚英文甚至为 5px，但本轮根代理没有专门测量这条页脚，不把它称为已实测。

根代理在 390×844 页面确认 `React / NestJS / MongoDB` 为 7px、`PERSONAL ARCHIVE` 为 7px、`PROJECT`/“精选档案”为 8px、竖排标语为 6px。项目摘要本身是 11px（第 326 行），不应与纯装饰英文一并缩小。

建议功能信息、标签和摘要以 12–14px 为起点重新排版；保留的装饰信息至少采用可读尺寸，放不下时减少文案。不是所有微缩英文都必须保留。桌面与手机目前的真实内容没有被证明发生溢出；根代理测得当前手机 `scrollWidth=375 < innerWidth=390`。这是 AC01/AC07 下的阅读质量改进，不应误报成当前布局已损坏。

### 3. 固定问候与英文标语重复，且关于标题出现双标点——一项真实小缺陷，其余为文案建议

当前公开 API 为 version 2，首屏实际是 `GOOD TO SEE YOU.` / `OH,\nHELLO.` / “来看看，这里藏着什么。”，真实项目为“个人任务管理”；个人介绍与联系仍为空。页面通过 [SiteStore](../../../frontend/src/store/site.ts#L21) 第 21–23 行读取 API；[默认数据](../../../backend/src/site/config/site.defaults.ts#L7) 第 7–15 行及前端 [加载占位](../../../frontend/src/pages/site/index.tsx#L29) 第 29–35 行不是所有线上文案的唯一来源。

- 真实小缺陷：[公开页组件](../../../frontend/src/pages/site/index.tsx#L325) 第 325 行把姓名拼成 `你好，我是${name}。`；当前 `name=HEY.`，因此显示“你好，我是HEY.。”。根代理已看到该结果。后续可避免给已有结尾标点的展示名再追加句号。
- 风格建议：同一问候在开场、主标题、侧文案重复；首屏侧文案在第 269 行，档案 `SELECTED WORKS` / `A FEW THINGS I MADE.` 在第 283–286 行，人物旁标语在第 311 行，阅读页脚标语在第 327 行。手机另有 CSS 生成的 `SMALL IDEAS. REAL THINGS.`，见样式第 318 行。保留主要问候和一个档案签名，减少与内容无关的重复小字，会让人物与作品更集中。
- 登录页 [第 178–180 行](../../../frontend/src/components/site-login/index.tsx#L178) 的 `WELCOME BACK`、“小小世界”和第 207 行“新的灵感”也是可选文案精简点。登录动作及错误提示已经清楚，不必改成营销文案。

不建议机械删除 `HEY.`、`OH, HELLO.` 或逼迫用户填职业口号；这是已选个人站语气。真实介绍未提供，不能编造身份、成绩、项目或联系方式。

### 4. 常规控件的间距与文字角色缺少统一节奏——仅风格与维护建议

可见源码例子：[公开页样式](../../../frontend/src/pages/site/style.module.less#L127) 第 127 行标题上间距 23px，第 137 行按钮间距 27px，第 176–181 行档案/纸页内边距混用 9、15、14、18、21、23px；[登录样式](../../../frontend/src/components/site-login/style.module.less#L45) 第 45–48 行表单间距 31px、字段间距 19px、主按钮最小高度 49px。宽字距的大写辅助文案同时使用多组 7–12px 字号。

建议后续精修先把重复控件归到少量 4px 间距级别、统一功能文字/辅助文字/装饰文字角色，再决定是否需要减少装饰。纸张错位、人物构图、图层旋转与光学对齐属于有意设计，不应为了满足“所有值为 4 的倍数”把它们机械取整。这些差异没有单独证明可用性故障。
