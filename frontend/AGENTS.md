# 前端 AI 开发约定

开始前先读取 [根开发约定](../AGENT.md) 与 [当前工作状态](../docs/ai/STATE.md)，再读取当前任务的 SPEC。本文件只补充 `frontend/` 范围的规则；接口合同以 [当前系统基线](../docs/specs/000-current-system.md) 为准，环境配置和启动步骤统一见 [根 README](../README.md)。

## 分层与实现

- 保持 `src/api/` → `src/store/` → `src/pages/` 分工：API 封装 HTTP，MobX store 管理业务状态与请求，页面管理表单、弹窗和展示。页面不直接调用 `fetch`。
- 复用 `src/api/http.ts` 的请求和错误解析；接口、类型与请求头的改动须与后端及 SPEC 同步。TypeScript 类型断言不等于运行时响应校验。
- 异步请求完成后，修改 MobX 可观察状态使用 `runInAction`；保留加载版本检查，避免较早的查询响应覆盖较新的结果。
- 维持写操作互斥和提交状态保护；修改加载、刷新或写入流程时，同时检查重复提交和读写交错情形。
- 复用现有 React、MobX、Ant Design、Less Modules 及代码风格；不要仅为偏好替换技术栈。

## 交互约定

- 编辑或删除成功后才更新列表、关闭弹窗；失败保留弹窗及错误信息。删除取消不发送请求，提交期间阻止重复操作和关闭弹窗。
- 列表、创建、编辑、删除、统计保留各自的错误状态。列表加载失败时保留已有列表并显示错误；统计失败显示未知值与重试提示，不用 0 代替失败。
- 任务总数来自后端统计；创建、删除成功后重新查询统计。统计查询失败不把已经成功的写入描述为失败。运行时长展示的是上次统计值。
- 表单校验用于交互提示，后端仍负责输入校验。新增交互在 SPEC 中写清正常、空数据、加载、失败和重试行为。
- `completed` 字段已存在，但目前没有完成状态切换功能；不能仅凭字段认定功能已实现。

## 验证与交接

在 `frontend/` 目录执行现有检查，按改动范围选择并记录实际结果：

```bash
npm run lint
npm run check
npm run build
```

`check` 验证 TypeScript，`build` 包含类型检查与 Vite 构建；构建时不必重复运行同等类型检查。当前没有前端 `test` 脚本或自动化交互测试，不得声称已通过不存在的测试。纯文档改动检查链接、命令和源码一致性即可。

涉及交互或接口改动时，按 SPEC 验证相应浏览器流程，并分别记录静态检查、构建、人工操作的结果；未执行的检查明确写“未执行”。完成后按根约定更新任务交接与状态，避免在这里追加会话流水账。
