# SPEC-004：服务器磁盘文件上传

- 编号：004；状态：已验证（本机、CI与线上上传）；更新日期：2026-11-10。
- 基准：`9b12524`，开始前 README/STATE 已有未提交部署与数据库交接，保留。
- 用户要求：用现有服务器磁盘接入图片、PDF、附件上传，并说明接入流程；已确认全部公开，仅站主可上传。
- 前置：[SPEC-003](003-personal-site.md)。仅替代 P24/P28「不提供新图片上传」的限制，不恢复独立作品档案或旧 `projects` 合同。

## 目标与范围

- 后台增加统一文件上传入口，项目封面可直接上传，Markdown 编辑器可上传图片或附件并插入对应语法。
- 延用 `SITE_ASSETS_DIR`、随机文件名、受控媒体 GET、Session → SiteOwner → CSRF；音频上传原合同保留。
- 文件存服务器独立持久目录，网站 Mongo 文档只保存 URL/Markdown；文件上传本身不修改站点版本。
- 图片支持 JPG/JPEG、PNG、WebP，最大 5 MiB；PDF、ZIP、TXT、DOCX/XLSX/PPTX 最大 20 MiB。附件是白名单，暂不支持可执行文件、HTML、SVG、旧版 Office 及任意格式。
- 不新增云服务、文件列表/删除/自动回收、私密文件、多文件并行、断点续传或压缩转换。前一轮仅本机开发；2026-11-10用户追加授权将上传功能提交、推送并通过现有自动部署上线，核对服务器配置并实际验证线上上传。

## 用户行为

- 「文件上传」分区选择文件，显示处理中、失败重试及本次上传的地址和 Markdown；空态说明格式、大小与公开访问含义。
- 项目封面上传成功只替换当前项目草稿封面；Markdown 上传成功在对应正文插入图片或下载链接，保留已有文字。正文超限不截断，保留原文及可复制的上传结果。
- 处理期间阻止重复上传、保存、退出及编辑交错；失败保留原封面/正文。身份变更或页面停用后，迟到响应不得写入新身份草稿。
- 所有文件自上传完成即能凭链接公开访问，即使未保存或项目被隐藏也不具备保密性；页面显示与链接引用仍需「保存全部」。

## 接口与数据契约

| 方法 / 路径 | 权限与输入 | 成功 | 失败 / 数据影响 |
| --- | --- | --- | --- |
| POST `/api/site/file-assets` | Session、站主、CSRF；multipart，唯一 `file`，无其它字段 | 201 `{url,name,mimeType,size,kind}` | 未登录401，非站主/未配置403，缺CSRF403；空/超限/类型不符/多文件400，不写文件 |
| GET `/api/site/assets/:filename` | 公开；UUID v4 + 允许扩展名 | 200 原始文件；图片/音频保持媒体展示，PDF与附件强制下载 | 非法文件名400，不存在404，不泄漏磁盘路径 |

- `url` 为本站 `/api/site/assets/<uuid>.<ext>`；`kind` 是 `image` 或 `attachment`；`name` 为去除目录/控制字符的显示文件名，最多150字符；`mimeType` 由后端判断；`size` 为实际字节数。
- 图片/PDF/ZIP容器核对文件签名（ZIP仅普通单卷，拒绝分卷和ZIP64），TXT核对UTF-8与二进制/控制字符；Office仅校验ZIP容器与扩展名，作为下载附件，不承诺文档可打开或查毒。客户端 MIME 可能为空或通用二进制，不以它取代文件内容校验。
- 随机名禁止覆盖；附件使用正确 MIME、`nosniff`、安全 `Content-Disposition: attachment`。若保留原下载名，元数据与文件放同一目录并安全处理；无元数据的历史媒体继续可读。
- 音频仍限15 MiB、MP3/WAV/OGG，旧 POST `/api/site/assets` 保持404。路径校验不接受目录穿越、任意相对链接或未知扩展名。
- 前端安全URL仅新增严格本站附件路径用于 Markdown 链接；图片位置仍只允许图片，外部HTTP(S)原规则保留。整站配置字段不变，无数据迁移。
- 文件与站点保存分离；当前不自动删除未引用文件，部署/回滚均保留整个媒体目录。
